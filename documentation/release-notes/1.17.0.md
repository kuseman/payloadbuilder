# Payloadbuilder 1.17.0 release notes

## Kafka catalog: new format `auto`, now the default

Kafka doesn't record what format a topic's values are in, so until now a query had to name the right `format` or fail
on the first value that didn't match. The new format `auto` looks at each value and decodes it as whatever it is:

1. **Schema-registry value** (Confluent wire format: byte `0x00` and a 4-byte schema id):
   - With the catalog property `schema_registry_url` set, the registry's schema type decides. Avro is decoded as
     with `format = 'avro'`. JSON Schema is decoded as the JSON after the header. Protobuf isn't supported and fails
     with a clear message.
   - Without a registry URL, a JSON Schema value still decodes as JSON. Any other schema-registry value is
     returned as text.
2. **JSON**: a value that parses completely as JSON (leading whitespace and a UTF-8 BOM are skipped).
3. **Text**: anything else, as a UTF-8 string. An empty value becomes the empty string.

Detection is per value, so topics that mix formats, or whose producers changed format over time, read correctly
row by row. `on_error` applies to `auto` as to the other formats. Keys are UTF-8 strings, as before.

The `avro` library is still an optional dependency. With `auto` it's only needed when a topic actually contains Avro
values; JSON Schema values decode without it.

### Changed default

`format` now defaults to `auto` instead of `json`. Values that are exactly one JSON value read the same as before.
Two kinds of value read differently:

- A value that isn't JSON at all used to fail the query and is now returned as text:

  ```sql
  -- 1.16.0: Value deserialization error at 0:0 | Failed to deserialize JSON value | JsonParseException: Unrecognized token 'Customer'
  -- 1.17.0: returns 'Customer 0' as the value
  select * from kafka#topic.customers x
  ```

- A value that starts with JSON but has more content after it used to return only the leading JSON value and
  silently drop the rest: `42 apples` read as `42`, and `{"a":1}{"a":2}` as `{"a":1}`. Under `auto` such a value
  isn't JSON, so the whole value is returned as text.

A value that is valid JSON is returned as JSON, as with `format = 'json'`: `42` is a number and `"x"` is the
string `x`. To get the exact text, use `format = 'raw'`. To keep the strict behaviour and fail on values that aren't
JSON, write `with (format = 'json')`.

### Clearer error for `format = 'avro'` on a schema that isn't Avro

A schema-registry value whose schema is JSON Schema or Protobuf used to fail with
`Failed to fetch Avro schema id <id> from all Schema Registry URLs`, although the fetch worked. It now fails with
`Schema id <id> is JSON, not Avro` (or `PROTOBUF`).
