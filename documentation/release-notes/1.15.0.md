# Payloadbuilder 1.15.0 release notes

## Breaking: `payloadbuilder-catalog` is split into one artifact per catalog

`payloadbuilder-catalog` used to be one jar that bundled every catalog, and all of their libraries
(`kafka-clients`, `mongodb-driver-sync`, `httpclient5`, HikariCP, mustache). From 1.15.0 each catalog is its own
artifact and brings only its own dependencies.

**`payloadbuilder-catalog` is no longer published.** Replace it with the artifacts for the catalogs you use.

Packages and class names are unchanged: you change Maven dependencies, not imports. Behaviour is unchanged.

| Catalog class | Artifact (groupId `se.kuseman.payloadbuilder`) |
|---|---|
| `se.kuseman.payloadbuilder.catalog.es.ESCatalog` | `payloadbuilder-catalog-es` |
| `se.kuseman.payloadbuilder.catalog.fs.FilesystemCatalog` | `payloadbuilder-catalog-fs` |
| `se.kuseman.payloadbuilder.catalog.http.HttpCatalog` | `payloadbuilder-catalog-http` |
| `se.kuseman.payloadbuilder.catalog.jdbc.JdbcCatalog` | `payloadbuilder-catalog-jdbc` |
| `se.kuseman.payloadbuilder.catalog.kafka.KafkaCatalog` | `payloadbuilder-catalog-kafka` |
| `se.kuseman.payloadbuilder.catalog.mongodb.MongoCatalog` | `payloadbuilder-catalog-mongodb` |

The classes in the root package `se.kuseman.payloadbuilder.catalog` (`CredentialsException`, `AuthType`,
`HttpClientUtils`) are in `payloadbuilder-catalog-common`. The catalogs that need it depend on it, so you only
declare it yourself if you use those classes directly.

### Migrating

Before:

```xml
<dependency>
  <groupId>se.kuseman.payloadbuilder</groupId>
  <artifactId>payloadbuilder-catalog</artifactId>
  <version>1.14.0</version>
</dependency>
```

After, for example with only the Elasticsearch and JDBC catalogs:

```xml
<dependency>
  <groupId>se.kuseman.payloadbuilder</groupId>
  <artifactId>payloadbuilder-catalog-es</artifactId>
  <version>1.15.0</version>
</dependency>
<dependency>
  <groupId>se.kuseman.payloadbuilder</groupId>
  <artifactId>payloadbuilder-catalog-jdbc</artifactId>
  <version>1.15.0</version>
</dependency>
```

### Client library versions

Each catalog declares its client library (`mongodb-driver-sync`, `kafka-clients`, `httpclient5`) at compile scope,
at the version it is built and tested with, so a catalog works on its own. An application that uses the client
itself can declare it directly, and Maven's nearest-wins rule picks the application's version. Stay on the same
major version as the catalog was built with.

As before, `avro` is an optional dependency of `payloadbuilder-catalog-kafka`: add it yourself to read Avro
messages.
