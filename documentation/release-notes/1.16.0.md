# Payloadbuilder 1.16.0 release notes

## Mongo catalog: new catalog property `tlsAllowInvalidCertificates`

The Java MongoDB driver doesn't support `tlsAllowInvalidCertificates` in the connection string (and `tlsInsecure=true`
only relaxes host name checks), so servers with self-signed or otherwise invalid certificates could not be queried.

| Key | Constant | Type | Default |
|---|---|---|---|
| `tlsAllowInvalidCertificates` | `MongoCatalog.TLS_ALLOW_INVALID_CERTIFICATES_KEY` | boolean (or the string `"true"`) | `false` |

When `true`, `MongoCatalog` accepts any server certificate and host name. It only takes effect when the connection
string turns TLS on (`tls=true`, `ssl=true` or `mongodb+srv://`); the property never enables TLS by itself.

> **Warning:** this turns off protection against man-in-the-middle attacks. Use it only for servers you trust, such as
> local or lab clusters.

Nothing changes for connections that don't set the property.
